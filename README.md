# FAST — исследовательская Python-версия

Проект переносит поведение старой DOS-программы FAST по данным из `fik.img`.
Из образа извлечены исходные `.PAR`, документация, EXE и шрифт CP866; исходные
файлы сохранены в `data/original`, а результаты анализа — в
`ORIGINAL_BEHAVIOR.md` и `REVERSE_ENGINEERING.md`.

## Запуск

Готовую Windows-сборку можно запускать двойным кликом по `FAST.exe`: Python и
библиотеки на компьютере пользователя не нужны. Файл `fast.log` создаётся рядом
с программой. Если эта папка защищена от записи, журнал автоматически
сохраняется в `%LOCALAPPDATA%\FAST\fast.log`.

Чтобы собрать `FAST.exe` самостоятельно:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt -r requirements-build.txt
.\build_exe.ps1
```

Результат появится в `dist\FAST.exe`. Для обычного запуска из исходников:

```text
cd financial_market_simulator
pip install -r requirements.txt
python main.py
```

В меню выберите любой кейс и пункт `Торговая сессия`. Для B01/B02, CA1–CA3,
OP1–OP3 и RE1–RE3 доступны все действия двойного аукциона: стрелки выбирают
бумагу и Bid/Ask, ввод `p.q`
выставляет заявку, `B` принимает Ask, `S` принимает Bid, `Esc`/`E` выходит.
Запись `p.q` использует формат FTS: слева находится целая цена, справа — число
бумаг. Например, `113.50` означает цену 113 и количество 50, а `12.7` — цену
12 и количество 7. Этот формат используется в книге и в последних сделках.
Остальные вкладки открывают рабочие учебные экраны: параметры меняются
стрелками, `D` показывает полный соответствующий текст FAST.DOC, `F10`
восстанавливает исходные параметры.
Параметр `--speed 10` ускоряет десятичный секундомер в десять раз; значение
`1` соответствует скорости оригинала.
По умолчанию окно открывается в масштабе 125%. Параметр `--scale 1.5`
запускает его в масштабе 150% (допустимо `0.5`–`5`).
Каждый экран рисуется на логическом холсте и масштабируется без потери
пропорций; окно также можно свободно изменять мышью.

## Современный интерфейс

Рабочие экраны получили современную тёмную тему с карточками, цветовой
подсветкой Bid/Ask, индикатором времени и отдельными панелями счёта. Клавиши
остались прежними: стрелки, Enter, Esc, B, S, F9 и F10 работают так же, как в
оригинале. Стрелки можно удерживать для непрерывного перемещения. В главном
меню разделы и пункты можно дополнительно выбирать мышью; клик по торговой
таблице выбирает инструмент и сторону заявки.

Главное меню устроено вертикально: `↑`/`↓` выбирают раздел или пункт,
`Enter`/`→` открывают его, `Esc`/`←` возвращают назад. Один клик по карточке
материала сразу открывает её; кнопка `Открыть` остаётся для управления с
клавиатуры.
Справа от выбранного раздела сразу показаны названия входящих в него
материалов. Клик по разделу открывает их выбор без промежуточного экрана со
счётчиком.
Во всех вложенных меню есть видимая кнопка `← Назад`, которая выполняет тот же
переход мышью.

Раздел `Настройки` управляет темой, размером шрифта, звуком, масштабом окна и
полноэкранным режимом. Доступны светлая и тёмная темы, а размер текста меняется
от 80% до 120%. Изменения сразу применяются и автоматически сохраняются в
`settings.json` рядом с программой; если папка защищена от записи, используется
`%LOCALAPPDATA%\FAST\settings.json`.
Стрелки `↑`/`↓` выбирают строку, `Enter` включает её редактирование, а
`←`/`→` меняют значение. Повторный `Enter` завершает редактирование. Мышью можно
сначала выбрать всю строку либо сразу нажать отдельную стрелку слева или справа
от значения.

`F11` включает и выключает полноэкранный режим. `Ctrl++` и `Ctrl+-` меняют
размер окна с шагом 10%; перетаскивание границы окна также запоминается.
Всплывающая подсказка объясняет действие кнопки при наведении мыши. Отдельный
экран основных сочетаний клавиш открывается из настроек или клавишей `F1` в
главном меню. Подтверждение выхода появляется только во время активной торговой
сессии, чтобы случайное нажатие не уничтожило текущий период.

Звук сделки проигрывается после покупки или продажи, а отдельный сигнал — после
завершения периода. Оба сигнала создаются программой и не требуют звуковых
файлов; их можно отключить одной настройкой.

Диагностический журнал сохраняется в `fast.log` рядом с `main.py` или EXE, а в
защищённой папке — в `%LOCALAPPDATA%\FAST`. В нём есть переходы по меню и полный
стек необработанного исключения. Если программа закрылась с ошибкой, приложите
этот файл к сообщению; старые журналы автоматически ротируются.

## Игра по локальной сети

Откройте в главном меню `Сетевая игра → Локальная сеть`. Доступны три режима:

- `Игра преподавателя` создаёт настраиваемую комнату на восемь студенческих мест;
- `Быстрая игра` создаёт воспроизводимый сбалансированный сценарий и подключает
  создателя как игрока-хоста;
- `Подключиться` принимает адрес вида `192.168.1.25:8765` и имя студента.

На экране подключения открытые комнаты в локальной сети находятся
автоматически. Выберите комнату стрелками и нажмите `Enter`; `F5` повторяет
поиск. Поле «Адрес сервера» редактируется мышью или через `Tab`;
`Ctrl+A` или `Delete` очищает его. Ваш собственный IP показан вверху и не является
полем ввода.

VPN и виртуальные сетевые адаптеры могут мешать автопоиску. Программа игнорирует
отказ отдельного VPN-маршрута и продолжает поиск в локальной сети. Если комната не
появилась, отключите VPN или введите адрес хоста вручную.

Адрес комнаты показан в правом верхнем углу экрана хоста. Все компьютеры должны
быть в одной локальной сети, а Windows может при первом запуске попросить
разрешить Python доступ к частной сети. По умолчанию используется TCP-порт
`8765`.
Поиск комнат использует UDP-порт `8766`, поэтому его также нужно разрешить для
частной сети.

Перед созданием преподавательской игры открывается экран настройки. На нём
можно выбрать B01, B02, CA1–CA3, OP1–OP3 или RE1–RE3, название комнаты,
число студенческих мест и роботов,
длительность периода, скорость реакции роботов, очередь заявок и доступность
подсказки F9. Для роботов отдельно настраиваются стиль поведения, разброс их
индивидуальной оценки бумаг и максимальный объём одной заявки. `↑`/`↓` выбирают
параметр, `←`/`→` меняют значение, `Enter`
редактирует название или создаёт игру, а `F5` создаёт игру из любой строки.

Сбалансированные роботы торгуют по своей оценке бумаги. Осторожные требуют
дополнительную выгоду в 2%, а агрессивные готовы принять цену с отклонением до
3%. Разброс `0%` даёт всем обычным роботам одинаковую расчётную оценку; при
`20%` каждый получает оценку в диапазоне 80–120%. Роботы типа «волк» всегда
знают точную расчётную стоимость, как в исходной программе.

Преподаватель видит деньги и позиции каждого участника. `Tab` переключает
наблюдаемого игрока, `Enter` запускает следующий период, `Space` ставит торги
на паузу, `E` досрочно завершает период. В ходе торгов и на экране результата
клавиша `R` открывает преподавателю пошаговый повтор всех заявок и сделок.
`←`/`→` перемещают по событиям, `Home`/`End` переходят в начало или конец,
`Tab` переключает портфель участника, а `Esc` закрывает повтор.
Игроки используют привычные стрелки,
цифровой ввод `цена.количество`, `B`, `S` и `F9`. В режимах CA, OP и RE справа
показывается соответствующий case HUD; `H` переключает его и портфель. Private
information RE передаётся отдельно каждому студенту, а будущий исход скрыт до
наступления периода. Повторный запуск подключения
с тем же именем возвращает студента на прежнее место после обрыва связи.

Расширенный запуск позволяет преподавателю выбрать `.PAR`, число мест,
роботов и длительность:

```text
python multiplayer.py admin --scenario data/original/B02.PAR --players 12 --bots 3
python multiplayer.py admin --duration 90 --reaction 4
python multiplayer.py admin --room-name "Семинар 7"
python multiplayer.py admin --robot-style cautious --robot-value-spread 10 --robot-max-quantity 20
python multiplayer.py admin --case "Case RE1" --seed 2026
```

Игрок может создать сценарий заданной сложности и seed. Одинаковый seed даёт
одинаковые ставки, выплаты, позиции и начальный капитал:

```text
python multiplayer.py host --difficulty hard --seed 2026 --players 6 --bots 4
```

Остальные участники подключаются по адресу, показанному хостом:

```text
python multiplayer.py join 192.168.1.25:8765 --name Студент-1
```

Сервер является единственным источником состояния: он проверяет заявки,
исполняет сделки, ведёт таймер и роботов. Клиент игрока получает только свой
портфель, а преподаватель — все портфели. Сетевые подключения и действия рынка
записываются в `fast.log`.

## Справочник и формулы

Все 22 пункта исходного оглавления FAST.DOC открываются клавишей `Enter` или
кликом мыши. После чтения статьи `Esc` возвращает в оглавление. Математические
выражения выделяются отдельными блоками; степени, греческие буквы и корни
отображаются в типографическом виде, например `σ² · Δt`. Деление в формулах
рисуется настоящей горизонтальной дробной чертой. Таблицы используют
моноширинный шрифт, границы строк и отдельное оформление заголовков, поэтому
столбцы сохраняют выравнивание.

Интерфейс масштабируется со сглаживанием, а начальный размер окна увеличен до
125%. Размер по-прежнему можно свободно менять мышью или параметром `--scale`.

## Статус переноса

Чтение B01/B02, дисконтирование, выплаты, портфель, двойной аукцион и
ранговая очередь реализованы; цены F9 и сценарии без сделок сверены с
сохранёнными DOS-наблюдениями. B03/B04, CA*, OP*, RE* и TutBO/TutCA/TutOP
теперь имеют рабочие экраны, а исходный текст каждого раздела доступен
клавишей `D`. CA1–CA3, OP1–OP3 и RE1–RE3 запускают полноценные торговые
сессии с активами, выплатами и ограничениями соответствующего кейса. В CA1
запрещены короткие позиции, в CA2 сделки проходят по фиксированным ценам, а в
CA3 короткие позиции разрешены. Опционные рынки используют внешнюю цену акции,
облигацию и выплаты put/call; в OP3 первоначально выписанные опционы закрыты для
торговли. В режимах эффективности моделируются описанные в FAST.DOC состояния
компаний и частные сигналы участников. Реализованный случай выбирается случайно,
а его номер и выплаты показываются после последнего периода.

Для воспроизводимости seed каждой такой сессии записывается в `fast.log`.
Параметры восстановлены по FAST.DOC и наблюдаемому интерфейсу оригинала;
недоступные внутренние константы DOS-исполняемого файла заменены описанными в
документации вероятностными правилами.
Торговый экран сохраняет общую книгу заявок, но справа использует отдельный HUD
для семейства кейсов. В CA1–CA3 это пересчитываемые после каждой сделки
ожидаемый капитал и показатель `Дисперсия` (выборочное стандартное отклонение).
В RE1–RE3 показаны payoff-матрицы, личные сообщения `NOT ...` для обоих
периодов и вычисленный по разрешённым ячейкам диапазон стоимости. В OP1–OP3
отображаются параметры биномиальной модели, текущая внешняя цена, страйк и уже
реализованная часть пути акции. B01/B02 показывают потоки выбранной облигации и
её расчётную цену. Нижняя часть во всех торговых режимах содержит Cash, Int,
ID, выбранную бумагу, три последние сделки именно по ней и контекстную справку.
В B01/B02 и пользовательских BIDASK-уровнях работают остальные участники.
Они используют число роботов и волков, задержку реакции и стратегию из `.PAR`,
исходный генератор случайных чисел, расчётные оценки 80–120% и четыре действия
оригинала: Bid, Ask, покупку и продажу. Python `float` не повторяет Real48
побитово, поэтому решения точно на границе оценки могут отличаться от DOS.
После завершения каждого периода клавиша `R` открывает повтор локальной сессии
с книгой заявок и портфелями на момент каждого принятого действия.

После последнего периода клавиша `F2` открывает итоговый отчёт. В нём показаны
начальный и итоговый капитал, результат торговли, число и средняя цена сделок,
результат по каждой бумаге, график прогнозного капитала, очки и место участника.
В локальной игре и у преподавателя `Tab` переключает участника, а `↑`/`↓` —
бумагу. В сетевой игре студент видит только собственный отчёт. `F3` сохраняет
версии CSV и HTML с графиком в папку `Документы\FAST reports`; дополнительные
библиотеки для просмотра или экспорта не нужны. Нереализованный результат после
последнего периода равен нулю, поскольку все выплаты по бумагам уже начислены.

## Свои уровни

При работе с готовым `FAST.exe` пользовательские уровни удобнее хранить в
`levels.json` рядом с программой. Они появляются во вкладке `Свои уровни` после
перезапуска, а сам EXE пересобирать не нужно. Пример файла:

```json
[
  {
    "name": "Семинар — облигации",
    "scenario": {
      "periods": 2,
      "duration_ticks": 600,
      "rates": [8, 12],
      "names": ["Купон", "Zero"],
      "payments": [[10, 110], [0, 100]],
      "cash": 1500,
      "positions": [10, 5],
      "score_parameters": [0, 0, 10000, 6],
      "queue": true,
      "robots": 4,
      "wolves": 1,
      "reaction_ticks": 30,
      "strategy": 1,
      "hints": true,
      "robot_style": "balanced",
      "robot_value_spread": 0.2,
      "robot_max_quantity": 25,
      "goals": [
        {"kind": "trades", "target": 3, "title": "Совершите три сделки"},
        {"kind": "profit", "target": 100},
        {"kind": "position", "instrument": 0, "target": 8, "maximum": 12}
      ]
    }
  }
]
```

Программа проверяет размеры таблиц, числовые границы и обязательные поля при
запуске. Ошибка в файле записывается в `fast.log`, а встроенные уровни остаются
доступны.

При запуске из исходников уровни также можно задавать Python-кодом в
[market/levels.py](D:/Progs/OR/financial_market_simulator/market/levels.py).
Каждый объект `CustomLevel` автоматически появляется в `Свои уровни`. Например:

```python
from market.config import Goal, Scenario
from market.levels import CUSTOM_LEVELS, CustomLevel

CUSTOM_LEVELS.append(CustomLevel(
    "Мой уровень",
    Scenario(
        periods=2,
        duration_ticks=600,       # 60 секунд на период (0.1 сек)
        rates=(8, 12),             # процентные ставки по периодам
        names=("Купон", "Zero"),
        payments=((10, 110), (0, 100)),
        cash=1500,
        positions=(10, 5),
        score_parameters=(0, 0, 10000, 6),
        queue=True,
        robots=4,
        wolves=1,
        reaction_ticks=30,
        strategy=1,
        hints=True,
        robot_style="balanced",
        robot_value_spread=0.2,
        robot_max_quantity=25,
        goals=(
            Goal("trades", 3, title="Совершите три сделки"),
            Goal("profit", 100),
            Goal("position", 8, instrument=0, maximum=12),
        ),
    ),
))
```

В `payments` должна быть одна строка на бумагу и по одному числу на каждый
период. `positions` содержит начальные количества бумаг. `duration_ticks` и
`reaction_ticks` используют десятые доли секунды, как исходный `.PAR`.
`robot_style` принимает `cautious`, `balanced` или `aggressive`.
`robot_value_spread` задаёт разброс оценки от `0` до `0.5`, а
`robot_max_quantity` ограничивает объём заявки значением от `1` до `99`.
Все три поля необязательны: без них сохраняется исходное поведение с разбросом
20% и заявками до 99 единиц.
Поле `goals` необязательно. Поддерживаются четыре типа учебных целей:

- `capital` — итоговый капитал не ниже `target`;
- `profit` — результат относительно стратегии без торговли не ниже `target`;
- `trades` — не менее `target` исполненных сделок;
- `position` — позиция по бумаге с индексом `instrument` не ниже `target` и,
  если задано, не выше `maximum`.

Необязательное поле `title` заменяет автоматически сформулированное условие.
Во время сессии `F4` открывает текущий прогресс. Локальный просмотр целей
приостанавливает таймер; в сетевой игре данные обновляются с сервера. После
последнего периода экран показывает окончательный статус каждой цели. В быстрой
сетевой игре автоматически создаются цели по числу сделок и результату торговли.
Для динамического добавления уровня перед вызовом `main.main()` можно вызвать
`market.levels.add_level("Имя", scenario)`. Пользовательский уровень использует
тот же экран BIDASK, двойной аукцион, F9, расчёт выплат и клавишу `--speed`.

## Торги

Вкладка `Торги` содержит `Инструкция` с полным описанием правил и отдельное
`Знакомство` — пошаговый урок из оригинального `DEMO.EXE FTS_TUT.SLD`. Он
показывает рабочий экран, формат заявки, улучшение Bid/Ask, очередь, покупки,
продажи, короткую позицию, ошибки количества и расчёты периода. Урок использует
клавиши F1, PgUp/PgDn, Home, B, S, Backspace, Enter и F10/Esc так же, как
слайдовая демонстрация DOS. Начиная со знакомства с рынком, пояснения остаются
на экране вместе с книгой заявок, а соответствующая область мигает. Стрелки
перемещают рамку между отдельными ячейками Bid/Ask. После завершения урока или
сессии программа возвращается в главное меню.
