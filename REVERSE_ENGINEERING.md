# Журнал reverse engineering

## Уровни уверенности

* CONFIRMED — непосредственно прочитано в конфигурации или восстановлено из кода.
* HIGH CONFIDENCE — подтверждено наблюдением оригинала (в пределах эксперимента).
* LIKELY — сильные косвенные признаки, остаётся проверка.
* UNKNOWN — пока не восстановлено; Python не должен придумывать замену.

Утверждения только из руководства ниже помечены отдельно как «документировано»:
наличие текста CONFIRMED, совпадение с исполняемым автономным модулем не следует
из этого автоматически. Руководство охватывает также сетевую систему.

## Воспроизводимость

Инвентарь и SHA-256 всех 35 файлов: `data/converted/inventory.json`.
Исходный образ не изменялся. Для DOS используется `data/reference_work/`,
а не каталог с сохранёнными оригиналами. Образ подключён с `-ro`.
Инструменты исследования: 7-Zip 26.00, Python 3.11, Capstone 5.0.9,
DOSBox-X 2026.08.31 (portable, Windows x64, SDL1), Pillow для захвата окна.
DOSBox-X получен из официальных releases:
https://github.com/joncampbell123/dosbox-x/releases/tag/dosbox-x-v2026.08.31
Исходники/документация эмулятора: https://dosbox-x.com/wiki/Home

`tools/disassemble.py` показывает **смещения в файле**, а не runtime-адреса.
Для MZ far-адрес преобразуется как `header_bytes + segment*16 + offset`.
Relocations при загрузке добавляют load segment. Линейный дизассемблер может
принять строки и таблицы за код; наличие листинга не означает декомпиляцию.
Capstone иногда печатает CWDE/CDQ вместо 16-битных CBW/CWD для 98h/99h.

Python-реализация текущего уровня находится в `market/`: `config.py` читает
B01/B02.PAR, `calculations.py` содержит подтверждённые формулы, а
`orderbook.py`/`engine.py` и `modules/bidask.py` дают проверяемую торговую
сессию B01/B02. Роботы намеренно не вызываются до завершения сверки ветвей
стратегии 0/1.

## Карта BIDASK.EXE

MZ header 0xF20, entry 0000:4EBB = file 0x5DDB. Основной CS начинается
с file 0xF20; библиотечный сегмент A60h — с 0xB520; DS C0Fh — с 0xD010.
Перечисленные DS-адреса относительные, не абсолютная память DOS.

| DS | Назначение |
|---|---|
| 0788..078B | 32-битное состояние RNG |
| 088A... | ставки (word), далее матрица выплат |
| 11F7 | разрешение подсказки F9 |
| 11F8 | очередь |
| 1592..15A9 | четыре Real параметра очков; смысл всей четвёрки требует проверки |
| 16AA | номер стратегии |
| 16C4..16C7 | реакция роботов, longint |
| 16C8..16CB | длительность периода, longint |
| 16CC | число периодов |
| 16CE | число бумаг |
| 16D0 | число роботов |
| 16D2 | число волков |
| 176A..176F | деньги игрока, Real |
| 1750 + i*104 + j*8 | оценка робота j для бумаги i (Real), далее количество (word) |
| 1C06 | текущий период |

Исследованные подпрограммы: uniform interval 0x123F, PV 0x1722,
future capital 0x190F, PAR reader 0x57BA, main 0x5DDB,
runtime guard 0x75C8, RNG 0xC71F/0xC758.
Расшифрованные диапазоны сохранены в `data/converted/disassembly/`.

## Эксперименты

1. Прямой `BIDASK B01.PAR`, чистый DOSBox — возврат в DOS до заставки.
2. `HEAD 11`, копия файлов на C:, исходный образ на A: — заставка и торговый
   интерфейс. Двоичные файлы не патчились, механизм запуска не обходился.
3. B01, оригинальные параметры, SPACE затем F9 — 90.240 / 51.200.
4. B01, только duration=30 (3 секунды), остальные поля исходные; SPACE для
   начала и переходов, без заявок. Итог на экране: 4597 в каждом столбце,
   2.76 очка. Это ограниченный reference case, не доказательство работы роботов.

Ввод для экспериментов: `tools/make_keyplay.py` генерирует маленький DOS COM,
который по BIOS-таймеру добавляет заданные клавиши через INT 16h AH=05h.
Он устанавливается только внутри исследовательского эмулятора; закрытие
эмулятора удаляет его состояние. Файлы приложения остаются без изменений.
Воспроизведение по BIOS ticks не является точным replay исходного RNG-потока.
Захват окна Windows: `tools/window_probe.py`. PostMessage-ввод в SDL1 не
сработал; для повторения экспериментов использовать KEYPLAY, не `--keys`.

## Противоречия и ограничения

* B01/B02: 9999 в документации против 10000 в PAR.
* B04: в документированной функции очков скачок у 5000; не «исправлен».
* OP1/2: текст называет u=2 точным, хотя exp(2.4/sqrt(12)) отличается от 2;
  текст о стандартном отклонении также расходится с формулой. Приоритет за EXE.
* OP2: раздел очков говорит об одном периоде, само упражнение — о двух.
* OP3: текстовые типы A/B и таблица 1/2 требуют сверки по EXE.
* Программная Real48 арифметика отличается от Python float. Пока восстановлен
  алгоритм формул, а не побитовая совместимость всех операций.
* Остальные EXE просмотрены по заголовкам/строкам/руководству, но не полностью
  декомпилированы. Нельзя называть исследование всех их алгоритмов завершённым.
